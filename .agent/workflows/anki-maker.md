# Anki 카드 생성 프롬프트 

`$ARGUMENTS`을 기반으로 Anki 카드를 생성해줘 

## 출력 형식

```markdown
## [질문 제목]

<details>
<summary>꼬리 질문</summary>
<div>

- 실제 꼬리 질문 1 (예: "클로저의 메모리 관리는 어떻게 이루어지나요?")
- 실제 꼬리 질문 2 (예: "클로저를 사용할 때 주의할 점은 무엇인가요?")

</div>
</details>

<details>
<summary>답변 보기</summary>
<div>

**메인 질문 답변**

[개념 정의 → 원리 → 예시 → 활용 → 관련 개념 순서로 자연스럽게 연결된 완성된 답변을 작성.
"~입니다", "~했습니다" 등 실제 설명 어투로 작성.
플레이스홀더가 아닌 구체적인 내용, 코드 예시, 수치, 출처를 포함.]

- 핵심 포인트 💡:
  - 실제 핵심 개념 설명 (예: "클로저는 함수와 그 함수가 선언된 렉시컬 환경의 조합입니다")
  - 구체적인 원리나 동작 방식 (예: "외부 함수의 변수를 내부 함수가 참조할 때 발생합니다")
  - 실무 활용 사례 (예: "데이터 은닉, 팩토리 패턴, 이벤트 핸들러에서 주로 사용됩니다")

- 개념 정의와 원리
  - 구체적인 설명과 함께 출처 명시
  - [출처명](링크)
  - > 위 출처에서 "원문 인용" 이라고 명시되어 있음.

- 실제 동작하는 코드 예시
  ```언어
  // 구체적이고 완성된 코드
  ```

- 활용 방법과 실무 사례
  - ✅ 올바른 사용: 구체적인 예시
  - ❌ 흔한 실수: 구체적인 안티패턴

- 성능/트레이드오프
  - 구체적인 수치나 비교 테이블

---

**꼬리 질문 1: [질문 내용 반복]**

💬 면접 답변 (1-2분 분량)

[면접관에게 직접 말로 전달할 완성된 답변을 작성.
개념 정의 → 원리 → 예시 → 활용 순서로 자연스럽게 연결.
"~입니다", "~했습니다" 등 실제 면접 어투로 작성.

예: "클로저의 메모리 관리는 가비지 컬렉션과 밀접한 관련이 있습니다. 클로저가 외부 함수의 변수를 참조하고 있으면 해당 변수는 메모리에서 해제되지 않습니다. 예를 들어... (구체적인 코드 예시와 함께 설명) ...이러한 이유로 클로저를 사용할 때는 메모리 누수를 방지하기 위해 불필요한 참조를 제거하는 것이 중요합니다."]

- 출처: [출처명](링크)
- > 위 출처에서 "원문 인용" 이라고 명시되어 있음.

---

**꼬리 질문 2: [질문 내용 반복]**

💬 면접 답변 (1-2분 분량)

[면접관에게 직접 말로 전달할 완성된 답변을 작성.
개념 정의 → 원리 → 예시 → 활용 순서로 자연스럽게 연결.
"~입니다", "~했습니다" 등 실제 면접 어투로 작성.

예: "클로저를 사용할 때 주의할 점은 크게 세 가지입니다. 첫째, 메모리 누수입니다... 둘째, 성능 이슈입니다... 셋째, 변수 공유 문제입니다... (각각 구체적인 예시와 함께 설명) ...따라서 이러한 점들을 고려하여 클로저를 적절히 활용하는 것이 중요합니다."]

- 출처: [출처명](링크)
- > 위 출처에서 "원문 인용" 이라고 명시되어 있음.

</div>
</details>
```

## 작성 규칙

### 답변 작성 요구사항 (필수)

답변은 **실제 사용할 수 있는 완성된 답변**으로 작성해야 합니다:

1. **실제 내용 작성**
   - 플레이스홀더(`[내용]`)가 아닌 실제 내용이 채워진 답변
   - 구체적인 코드 예시, 수치, 비교 테이블 포함

2. **출처 명시**
   - 각 내용마다 `[출처명](링크)` 형식으로 표기
   - 출처 바로 다음 줄에 `> 위 출처에서 "원문 인용" 이라고 명시되어 있음.` 형식으로 실제 원문 제공
   - 출처를 복사할 수 있게 markdown 형식으로 명시
   - 기술적 주장에는 반드시 출처 링크와 근거 제시

3. **자연스러운 구성**
   - 바로 활용할 수 있는 자연스러운 문장 구성
   - "~입니다", "~했습니다" 등 실제 설명 어투로 작성

4. **핵심 집중**
   - 질문에 대한 직접적인 답변만 제공

### 답변 구조

**기본 흐름**: 개념 정의 → 원리 → 예시 → 활용 → 관련 개념 순서로 자연스럽게 연결

**구성 요소**:
- 핵심 포인트 💡: 3-4개 요점 정리
- 구현 예시: 실제 동작하는 코드
- 정답/오답: ✅ 올바른 방법, ❌ 흔한 실수
- 성능/트레이드오프: 구체적인 수치나 비교
- h tag 사용 금지 li tag depth로 구분
- markdown 문법으로 작성

### 작성 시 주의사항

1. **기술적 정확성**: 불확실한 내용은 웹 검색으로 확인
2. **실제 코드**: 동작하는 구현 예시 포함
3. **출처 명시**: 기술적 내용에는 출처 제공
   - 출처 형식: `[출처명](링크)`
   - 출처 다음 줄: `> 위 출처에서 "원문 인용" 이라고 명시되어 있음.`
4. **단계적 깊이**: 개념 → 원리 → 예시 → 활용 → 심화 순으로 깊이 있게 작성
5. **실무 연결**: 이론에 그치지 않고 실제 사용 사례 포함

### 금지 사항

- 추측이나 불확실한 정보 제공
- 질문과 무관한 부가 설명
- 검증되지 않은 내용
- div 태그 밑에 markdown이 들어오는 경우 반드시 사이에 공백이 있어야 함
